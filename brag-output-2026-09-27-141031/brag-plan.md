# Task Lantern — from uncertainty to a clear view

## Direction
Start with the problem: a busy coding agent may be progressing, blocked, or waiting for the user. Introduce the workspace as the answer, then explain thread selection, questions, deeper details, and agent-published updates. Keep the spoken product introduction and full title card at the end. Add a small Task Lantern logo and name at the top left during the walkthrough.

Use thin, restrained highlights anchored to actual DOM elements in the recording. Each highlight follows the narration: current step, blocker, required answer, selected thread, question, waiting action, reply location, expandable details, current plan step, publication metadata, and local file status. No numbered callout strips. Reveal actual spoken words in the top caption with a short opacity fade and stable layout. Preserve whole-page fades.

Demo labels and the in-app brand are hidden only in the isolated recording profile. The interactive demo shipped with the repository is unchanged. Footage uses fictional task data and scripted interaction.

Captions use 12 short phrases from the unchanged narration. Local whisper.cpp token alignment provides their timing; script words and punctuation remain authoritative. All existing footage, highlights, scene timings, and audio are reused.
